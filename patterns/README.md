# Patterns

Patterns are reusable ways to improve proposals and repository decisions. They are not compulsory stages, scoring rubrics, or sources of authority.

- [`quality-signals.md`](quality-signals.md) — evidence that a proposal may be approaching the promotion boundary.
- [`common-failure-modes.md`](common-failure-modes.md) — recurring ways proposals become generic, inflated, or misleading.
- [`contribution-modes.md`](contribution-modes.md) — high-value ways to help without creating a new proposal.
- [`experiment-patterns.md`](experiment-patterns.md) — ways to learn before committing to a full build.
- [`issue-stewardship.md`](issue-stewardship.md) — how to keep an Issue body useful as its thread grows.

A new pattern should arise from repeated repository experience or clearly identified external practice. Do not populate this directory with speculative pattern lists merely to make it appear complete.
