# Build to learn before building to scale

Agentic coding lowers the cost of implementation, but cheap implementation can still create expensive distraction.

The smallest meaningful exploration is not necessarily the smallest amount of code. It is the least effort that can change a decision, reveal the intended experience, invalidate a key assumption, or expose a decisive constraint.

Useful explorations may be:

- a concierge or manual simulation;
- a storyboard or interaction sequence;
- a paper prototype;
- a technical spike against the hardest dependency;
- a fake-door test conducted ethically;
- a narrow end-to-end prototype;
- a comparison with an existing workaround;
- an expert review;
- a one-day use diary;
- an intentionally ugly but informative implementation.

Do not build a broad product merely because agents make that possible. Build enough to learn what reasoning alone cannot establish.
